## 一、装备系统：现状盘点与 SexyMUD 方案适配

### 1.1 本项目现状（旧版 js/，ADR-003 定为设计参考）

**核心模型：模板 × 运行时实例。**

- **模板**：`ITEMS` 中 `type:'equip'` 条目，带 `slot` 与基础属性（`js/data.js:40`-`62`，21 件：4 剑 4 甲 3 饰品 + 10 件妖物专属异宝）
- **实例**：`{uid, id, rarity, affixes[]}` 存 `S.gear`，`S.gearSeq` 自增发号；槽位 `S.equip` 只存 uid（`js/game.js:41`、`107`-`109`）
- **稀有度**：四档 = 属性倍率 + 词条条数（寻常×1.0/0 词条 → 绝世×1.5/3 词条，掉率 70/20/8/2%，炼器等级抬稀有度）（`js/data.js:156`-`161`、`js/game.js:85`-`95`）
- **词条**：池仅 4 条纯数值（锐锋/罡气/浑厚/通明 → 攻/防/血/暴），数值按装备自身主属性量级缩放 ±20%（`js/data.js:164`-`169`、`js/game.js:88`-`93`），同装备词条不重复
- **属性聚合**：`gearStats` = 基础×倍率 + 词条；`equipBonus` 遍历三槽求和后进 `playerAtk/Def/MaxHp/Crit`（`js/game.js:113`-`119`、`149`-`158`）
- **战斗耦合**：极浅——"有没有武器"切动词池（sword/fist）+ 按 `CTEXT.moves[武器id]` 抽招式名（`js/game.js:278`-`283`）
- **获取**：炼器配方 11 条（必定成功，产出走 `makeGear`，`js/game.js:414`）+ `GEAR_DROPS` 妖物专属掉落池（8 档掉率 7~15%，与配方零交集，`js/game.js:347`-`353`）
- **回收**：只有卖出换灵石（`js/game.js:480`-`488`）

新架构已定调：`packages/content/src/types.ts:52`——"稀有度与词条是运行时实例化概念，不属于内容包"，content 只收模板（`Item.slot/bonuses` + `GearDrop`）；engine 目前零装备概念。

> 【2026-09-03 被 ADR-016 修正】上句所引"不属于内容包"定调有误：档位词表
> （稀有度表/词条池/概率）属 content 包（SPEC:55/63 与本文件 §1.4 一致，
> §1.1 与 §1.4 的矛盾由此裁决闭合）；实例化**机制**仍属引擎。修复路线见
> `docs/audit/2026-09-03-engine-content-isolation-audit.md` §八。

**主要短板**：
1. 词条池太小且全是数值词缀——刷到绝世只是数字更大，构筑空间为零
2. 无词条阶位，稀有度只给条数不给质量
3. 无装备循环（分解/洗练/重铸），出货即终点
4. 槽位键名在 `game.js` 硬编码三处（init/迁移/`isWorn`，`js/game.js:41`、`58`、`465`），加槽必须改代码
5. 掉落池按敌人写死，秘境分层没有"层数→底材池"通路
6. 词条加成与丹药 buff 是两条独立计算路径（`equipBonus` vs `buffMult`），未来数值来源会继续分叉

### 1.2 SexyMUD 方案（ADR-0005/0012/0015 + `schemas/equipment.schema.json`）

**底材（base）× 词缀（affix）分离**（schema 用 `oneOf` 分流两类条目）：
- 底材 = `slot + floorRange(掉落层数段) + tierRange(词缀阶位天花板 T1~T3) + preferredTags(偏好标签) + inherentModifiers(固有词条，固定非随机)`；**底材分层**——高层掉另一个底材条目（换名换美术），明确否决 `itemLevel` 缩放
- 词缀 = `tiers`（3 阶数值表）+ `feature`（机制型特色词缀，如"你的中毒会传染"，用 condition+primitive 表达，引擎零新增）

**8 步掉落管线**（ADR-0012 #9，数据可配置不可写死）：
`① 掉不掉 → ② 按秘境层数筛底材池 → ③ 选底材 → ④ 掷稀有度 → ⑤ 按稀有度定词条数 → ⑥ 标签加权抽词缀 → ⑦ 按 tierRange 掷阶位 → ⑧ 附加固有词条`。口诀：**稀有度是因，词条数是果**。本项目旧版 `makeGear` ≈ 其中 ④⑤⑥ 三步。

**标签化词缀倾向**：底材只声明 `preferredTags`，词缀自带 `tags`，`权重 = 基础 × (1+匹配数×加成)`；新词缀带上 tags 自动被所有相关底材青睐，扩池零改动。

**修饰符聚合管线**：固定值 → 加法百分比 → 乘法区；词缀、心法、丹药 buff 全部产出修饰符走同一条管线，禁止绕过管线直改属性——"先于战斗系统实现"的地基设施。

**装备循环**：掉落 → 穿戴 + 分解（得材料）+ 洗练（材料重随单条词条数值，底材 `tierRange` 数据上锁死天花板）。词缀重铸、底材打造、镶嵌 socket 均留后续（socket 仅数据预留，MVP 不做）。

**流派涌现**（ADR-0015）：词缀可带 `condition: {moveId}` 定向强化某招式；玩家反复挑强化同一招式的装备就成了"专精"，但系统里没有叫专精的东西。换一套装备=换流派。

### 1.3 差距与扩展空间

| 维度 | 本项目现状 | SexyMUD | 引入成本 |
|---|---|---|---|
| 掉落管线 | ④⑤⑥ | ①~⑧ 全链 | 中 |
| 词条质量 | 无阶位 | T1~T3 阶位表 | 低 |
| 词条池 | 4 条纯数值 | 20+ 条×3 阶 + 特色词缀 | 低（纯内容） |
| 数值来源 | 词条/丹药两路分算 | 统一修饰符聚合 | 中（动地基） |
| 槽位 | 3 槽硬编码 | 数据化（dimensions.json） | 低 |
| 成长循环 | 只有卖出 | 分解+洗练（+远期重铸） | 中 |
| 构筑 | 无 | 标签联动/condition 定向 | 高（依赖修饰符+招式体系） |

**结论：有扩展空间，且是"补全管线"而非"推翻"。**

### 1.4 适配方案（修仙化，不照搬）

**术语**：底材→**器胚**、词缀→**铭纹**、阶位→**纹阶**、洗练→**重铸铭纹**、分解→**熔炼（得器屑）**、固有词条→**胚纹**。稀有度沿用寻常/精良/罕见/绝世，零迁移成本。槽位保留 3 个起步（法器/护体/灵饰）但**数据化**，为法宝、外袍留门。

**架构落点**：
- **content 包**：新增 equipment 节（器胚表 + 铭纹表，schema 仿 oneOf base/affix 结构但大幅简化）；稀有度/槽位作为 config 节数据化——符合"新内容=新 JSON"硬原则
- **engine 包**：`rollGear` 实例化纯函数（RNG 可注入、发事件流事件）+ 掉落管线最小核（先补 ⑦ 阶位；②层数筛选留给秘境票）+ **修饰符聚合**（`equipBonus`/`buffMult` 两路统一成 flat→加法%→乘法区一条管线，转生天赋将来直接复用）
- **校验**：器胚/铭纹 schema 走现有 `validateContent` 子集（已支持 pattern/enum/边界）；语义检查（tierRange ≤ 全局上限、掉落池引用存在）进 `validateContentPack`

**分期**（对齐 CONTEXT.md ADR-007"装备强化次之"）：
1. **地基**：修饰符聚合 + 槽位数据化（小，早做省返工）
2. **第一波内容**：铭纹池扩到 8~12 条（吸血/暴伤/连击/气血回复等）+ 2~3 条机制型特色铭纹 + 词条阶位 + 熔炼/洗练循环（器屑做消耗方，打通炼器经济）
3. **随秘境票**：器胚分层（层数段→器胚池）+ `condition:{moveId}` 定向铭纹（与 CTEXT.moves 招式体系联动）

**风险**：实例加字段（纹阶/tags）需版本化存档迁移——ADR-008 已定旧存档不迁移，现在做零包袱；新武器仍须在 CTEXT.moves 注册招式名（已有 fist 兜底）；uid 事件参数 `+arg` 转数字惯例继续遵守。

## 二、七系（系别）系统：现状盘点与适配

### 2.1 SexyMUD 两代设计（ADR-0009 → ADR-0020）

**v1（ADR-0009，数值层）**：
- 伤害两层制：`兵刃层`（无属性、恒有、走防御）+ `系别层`（= 兵刃层 × 系别系数，7 个系数在 config）。不存在第三类伤害
- 正交矩阵：作用方式（内功/外功）× 系别性质（七系+无属性）= 2×8，互不耦合
- **玩家不设分系抗性**：抗性一律是条件修饰符（`condition: {element:"fire"}` 的 stat-modifier），角色 schema 0 字段、存档 0 数据——否决了"7 个抗性字段"方案
- 怪物亲和度 `affinities: {fire:-50, water:+30}` 是 config 字段，**只给 Boss/特色怪配**
- 相克做"变异"不做"削弱"：五行增减伤表被否——数值打折不产生玩法

**v2（ADR-0020，结构性修订，作废 v1 的 MVP 形态）**：
- 起因：MVP 里 5/7 系是纯数值系数，文字游戏里玩家无感——"5/7 的系别等于不存在，却占着七系的设计、内容与校验成本"
- 定案**结构签名**，每系占一个可观测的结构维度，禁止纯系数：

| 系 | 轴 | 签名 |
|---|---|---|
| 金 | 破防 | 「剑锋崩开他护心镜」→ 此后伤害档位 +1 |
| 木 | 疫毒 | DoT「毒气又深入一分」→ 可传染 |
| 水 | 滞缓 | 「他出手凝滞了半分」→ 对手攻击间隔延长 |
| 火 | 燃爆 | 灼烧 DoT → 叠满「轰的一声，火舌炸开」 |
| 土 | 守护 | 「土黄色劲气附体」→ 受击档位 −1 |
| 风 | 迅疾 | 「身形一晃已是两招」→ 自身攻击间隔缩短 |
| 雷 | 霆爆 | 暴击/连锁，专属文本 + 会心金框 |

- 硬判据：**关掉所有面板，只读战斗文本，能说出"我这套是火系还是风系"**；验收不过就砍系——"宁要 4 个真系，不要 7 个假系"
- 关键洞察：风（自身提速）与水（对手减速）公式近似等价，但文本体验完全不同——**数值等价 ≠ 体验等价**
- 反面也要可见：打水系怪用火系，必须读到「火舌刚起就被湿气压了下去」——被克制的挫败感也是系别存在感
- 配套反馈：**战斗摘要**（战后一行画像"火烧掉了他三成气血"，由签名产生而非伤害统计）+ **同对手对照**（存档 `lastEncounter`，"三日前苦战三十合，今日十一合击倒"）

### 2.2 接线方式（全部内容侧）

- `content/config/dimensions.json` 的 `element` 维度（金木水火土风雷+none），所有 schema `$ref` 维度表不写死枚举，引擎零写死
- 武功条目：`source` + `element` 两字段；怪物条目：`source` + `affinities`
- 文案：后果词库 **5 维分池**（damageBand × lifeBand × source × motion × element）+ 独立 `elementFlavor` 词库类型
- 实现复用 4 类原语：`armor-modifier` / `damage-over-time` / `rate-modifier` / `crit-modifier` + `on-crit`/`on-tick`/`on-stack-full` 触发时机（`docs/engine-reservations.md` §3/§6）

### 2.3 与本项目现状的兼容性

| 维度 | SexyMUD | SmallRpg 现状 | 可搬性 |
|---|---|---|---|
| 战斗形态 | 1vN、12 阶段伤害管线 | 1v1 挂机单拍结算 | ❌ 2×8、双防御、管线不搬 |
| 敌人差异 | element + affinities | 仅 `kind: claw/magic` | ✅ 加可选字段 |
| 状态/DoT | primitive 池 | 完全没有 | ⚠️ 前置工程 |
| 攻击节奏 | rate-modifier | 敌我 `attackInterval` 固定 | ✅ 最易做签名 |
| 暴击 | crit-modifier + on-crit | 已有 crit 体系 + 文案门控 | ✅ 雷系几乎免费 |
| 文案底子 | 5 维词库 | CTEXT 按伤害档分池（本就借鉴 ADR-0011） | ✅ 同构扩展 |
| 战后反馈 | 摘要 + 对照 | victory() 只有掉落汇总 | ✅ 成本极低收益高 |

**核心结论：搬思想不搬结构。** 搬三样：①每系一个机制签名（拒绝纯数值系）；②抗性走条件修饰符（不进存档，与装备调研的"修饰符聚合"地基是同一件事）；③签名必须能被玩家命名（"火烧流""毒磨流"）。SmallRpg 战斗日志是主要反馈载体，判据只是放宽而非失效。

### 2.4 适配方案（修仙化）

**术语**：SexyMUD 自己都把「元素」列入 Avoid，称**系别**。修仙语境"金木水火土+风雷"天然契合（五行灵根、雷法、风法），可直接沿用，称**灵系/系别**；无属性 = 「凡击」。

**每系签名适配到 1v1 挂机**：
- **雷·霆爆** → 暴击率/暴伤 + 暴击专属文案（现有 crit 体系，零前置）
- **金·破防** → 攻击附带破防：受击者 def 临时降低，后续伤害档位跃迁（引擎加临时 debuff 位）
- **水·滞缓** → 敌人 `attackInterval` 延长（attackInterval 是数据字段，加 modifier 即可）
- **风·迅疾** → 自身攻击间隔缩短（同上）
- **火·燃爆 / 木·疫毒** → DoT + 叠层爆发/传染（**前置：engine 最小状态原语 + on-tick/on-stack-full 时机**）
- **土·守护** → 受击减伤/受击档位下降（简化为临时减伤 buff）

**接线（全走 content，不碰引擎分支）**：
1. `types.ts` 加 `Affinity`；`Enemy` 加可选 `element?` + `affinities?`（只给 Boss 配，不填=无系别，**随票 #2 schema 扩全顺手预留，零破坏**）
2. CTEXT：先做最小版——`elementFlavor` 小池（起手/后果风味句），5 维全分池不急
3. 与装备扩展衔接：铭纹可带 `element` 与 `condition:{element}`——SexyMUD 装备影响穷举"系别加成"正是 #2 项
4. 玩家抗性 = 铭纹条件修饰符（"罡气：受火系伤害 −30%"），存档零新增字段
5. 秘境层 modifier（"此层火系伤害 +30%"）——留给秘境票
6. **战斗摘要 + 同对手对照**建议直接引入：`victory()` 加一行签名画像、存档加 `lastEncounter[enemyId]` 一个字段

**分期**：
1. **前置**：engine 修饰符聚合 + 最小 debuff/临时状态位
2. **第一波（4 个真系）**：雷/金/水/风（都不依赖 DoT）+ elementFlavor 文案 + Boss 亲和度 + 被克负面文案
3. **第二波**：火/木（等状态原语）+ 战斗摘要/同对手对照 + 铭纹系别联动
4. **验收借用 ADR-0020 判据**：只读战斗日志，能说出"这套装备是雷法流还是毒流"；说不出就砍系

**风险**：挂机下玩家逐拍读文案密度低——"战后摘要/对照"类一次性反馈才是放置品类的主要消费点；系别系数/亲和度全进 config；不引入 2×8、双防御、12 阶段管线。

## 三、SexyMUD 全面调研：其余可借鉴系统

> 覆盖其余 30 份 ADR 与引擎预留清单。按对 SmallRpg 的相关度排序；已在一、二部分详述的装备/七系不重复。

### 3.1 资源与离线结算：内力系统（ADR-0010）

- **持续回复模型 + 耗尽降级不归零**：资源耗尽 → 自动切换零消耗基础攻击，输出下降但战斗不中断——挂机体验的底线设计
- **离线稳态 O(1) 铁律**：任何资源机制必须保持"收支平衡点解析可解"，任何需要逐步模拟的资源设计都会让离线结算退化成回放（SmallRpg 离线收益同样是解析式，这条应升级为设计守则）
- **代价在另一个维度付账**：木·吸内有四重代价（不能吸干/转化率 40%/自身伤害 ×0.7/可抵抗），雷·背水是伤害 +50% 同时防御 −25% 且需主动维持——防止"纯数值打折"式假选择
- 内力是系别性格的载体（七系×内力映射表已定，v2 直接落 config）
- **适配**：SmallRpg 斗法无资源系统，可远期加"真元"；但"离线可解"与"另一维度付账"两条原则立即生效

### 3.2 灵兽：本质是装备的机制放大器（ADR-0013）

- 兽 = **一组修饰符 + 一段可声明叙事片段**，落在装备体系（独立随从栏不占装备槽）；引擎不认识"兽"，只认识"带 narrative 的装备"
- **三条边界**：不被攻击/无血量不会死/不独立行动——"替你挡下"实为减伤修饰符 + 叙事包装
- **机制放大器模型**：兽改造该系核心机制的参数而非复制伤害（木=毒扩散、火=引爆、水=延长、金=不衰减、土=减伤转移、风=提速、雷=on-crit 追加伤害）——零新管线
- 不引入第二个养成循环（随人物自动成长）；MVP 只做 2 只验证模型
- 独立内容集合的依据是**生产规则不同**（装备=底材×稀有度×词缀的密集结构 vs 兽=一系一只的稀疏结构），且掉落引用天然隔离
- 工程预留：致命判定拦截点、`chance` 参数、**效果实例 CD 进存档**（唯一动存档的项）
- **适配**：修仙"灵宠/驭兽"语境天然契合（灵兽袋），远期内容；三条边界与"装备化"原则直接继承

### 3.3 宗门三件套与"学过的不没收"（ADR-0014）

- 门派 = **武功池 + 缺省系别 + 生产加成**三件套，外加贡献货币
- **已学武功与门派解耦（最重要预留）**：学过的功法是玩家资产，门派只是获取来源——换派/偷师/叛派全部退化为"获取权限"问题，不碰资产模型
- 脉 = 武功池的归类**标签**而非玩家身份选择（可多持，靠装配选）；流派由玩家玩出来，不预设标签
- 门派节奏差异（爆发/持久/累积）是内容层调参，引擎不感知"节奏"概念
- **适配**：SmallRpg 宗门排最后（ADR-007），但"宗门=功法池+缺省灵系+生产加成"与"学过的不没收"现在就该写进 CONTEXT 作约定，避免将来返工

### 3.4 进度感与变强反馈（ADR-0019/0015）

- 境界突破 → 三根并行主轴（武功修习/空间探索/装备构筑）+ `recommendedPower` 推荐战力区间（软提示，校验器检查生命周期覆盖）+ 50 档"造诣"纯显示层（**不产生任何门槛**）
- xkx100 招式按等级逐档解锁（间距递增：0/10/20/…/200）——内容生产有现成蓝本
- **变强反馈四补法**：秘境推进纪录/最高伤害纪录/叙事分档/聚合指标；五层反馈节奏（即时/一场/跨场/长线/社会）
- 失去台阶式进度节点的补偿：招式解锁自带专属文本仪式 + 社会层称谓变化（NPC 敬称由档位驱动，纯内容表）
- **适配**：SmallRpg 境界称号已是纯显示层（方向一致）；秘境票直接用 recommendedPower；**纪录系统（历史最佳层数/最高单次伤害/最快击杀）成本极低**，正好放进成就票（ADR-007）；境界→称谓的"社会层"可低成本加

### 3.5 确定性与调度：放置游戏的地基（ADR-0022/0025）

- **确定性三禁**：`Math.random()` / `Date.now()` / 隐式定时器；随机走注入的种子化 RNG，时间 = tick 计数的纯函数
- **观察时补偿结算（最妙的一条）**：DoT"每 3 tick 跳 5 次"= 纯函数 `f(startTick, nowTick)`，被观察时一次性补齐欠的跳数并写回 `applied`——无定时器、无存储、无回调；**这是 DoT/状态系统/离线结算的标准实现**
- **db/ndb 持久化二分**：存档只进真状态；**未显式写入的字段不落盘**（内容改默认值时旧档自动跟随）；渲染缓存/会话态（ndb）禁止被游戏逻辑读取
- 调度六原语：Clock / 纯 stage 求值 / 补偿结算 / 到期桶 / 区域 tick / on-change 钩子
- **settings 三分法**：STRUCTURE（装配图，不进 settings）/ TUNING（数字，进 settings.json）/ POLICY（决策，另开 policy.json）；禁用 null 表示无限、时间单位写进键名、每组带 `formula` 字段
- 条件表达式用 **JSON 数组**（`{all:[...],any:[...],not:[...]}`）不用字符串 DSL——可被 schema 校验；拒绝文案也是内容数据
- 动作意图 = 可序列化 dict（同时是存档格式与网络格式）；规则集中在可替换的服务对象
- **适配**：新 engine 骨架已走对方向（ManualClock、事件流 drain/subscribe）；"观察时补偿结算"应成为离线收益与未来 DoT 的标准实现；"未写入字段不落盘"可替代当前 migrateXxx 幂等修补

### 3.6 内容工程纪律（ADR-0003/0029/0030 + spec/06）

- **id 一经发布不可变**；美术资产按约定路径引用（`assets/icons/<集合>/<id>.png`）+ 程序化占位符兜底——MVP 零美术可跑，后期补图零代码改动
- **校验分层**：schema 门禁在构建期（`content:check` 退出码即结果），引用完整性在加载期（注册表大声失败）——两层共同保证，不在引擎内重复 schema 校验
- **原型继承**：加载期展平、同集合内继承、`prototypeKey`=条目 id 且不参与继承、环检测双保险（门禁+注册表）、合并后字典序升序——"灰皮哥布林×持矛萨满"类变体靠继承不靠笛卡尔积
- **标签模型**：`{维度: [键]}` 对象形态、不带值（带值用属性）、引擎维护倒排索引支持跨集合批量查询；`flags`（裸布尔"有没有"）与 `tags`（归类"能不能批量捞"）分工并存；`element`（字段取值池）与 `elementTag`（标签维度）不合并
- schema 变更三处同步纪律：schemas/ + 引擎类型 + 字段约定文档
- **适配**：票 #2（content schema 扩全）直接照搬这批纪律；`prototypeKey`/`prototypeParent` 两个字段**第一天预留**（零成本，事后加是灾难）；tags/flags 分工进 content 包约定

### 3.7 战斗表现配比（ADR-0006）

- **叙事 >> 视觉**：全屏文本流为绝对主体，伤害数字行内嵌入文本，会心用金框强调；强度差异由**叙事档位**表达（片段数、后果词分档）——措辞升级就是特效
- **事件流从第一天携带完整呈现语境**（伤害占比、暴击标志、系别），后补会伤及存档与模拟器兼容性
- 掉落不打断叙事流（行内交代 + 结算段），不用浮动 toast——SmallRpg 现状（toast+日志）可对照评估
- **适配**：新 engine 事件结构的设计输入（语境字段第一天带全）

### 3.8 明确不搬清单

| 不搬 | 理由 |
|---|---|
| MUD 命令层/房间/出口/立场/别名/中文分词解析 | 游戏形态不同（图形放置 vs 文字 MUD） |
| 2×8 正交矩阵、双防御、12 阶段伤害管线 | 1vN 武侠战斗专用，1v1 挂机用不上 |
| 云后端/多人/权威端切换 | 单机优先（ADR-002） |
| 插件系统 | ADR-0027：先做对再拆开，边界需实现过才知道 |
| 波次/离线推进已废条目 | 放置语境反而适用，但 SmallRpg 离线规则自定 |

## 四、市面放置游戏调研

### 4.1 直接对标：Melvor Idle（本作定位即"类梅尔沃"）

- 20+ 非战斗技能 + 8 战斗技能；技能间经济闭环（采集→加工→战斗消耗→掉落反哺生产）
- **装备槽 10+**（头/披风/颈/武器/弹药/身/盾/腿/手/靴/戒）+ **被动槽**（击败特定副本"Into the Mist"解锁）+ **召唤兽槽**（召唤兽 synergy 组合）+ **多套装备一键切换**；近战/远程/法师**战斗三角相互克制**，针对怪物换套装备是核心策略
- **Mastery 熟练度**：每个动作/物品独立等级（第二成长轴，把内容量翻倍）
- **自动化即奖励**：auto-eat（自动进食防死）、auto-loot、自动施法、auto-slayer——**后期 QoL 是解锁物而非默认**，手动操作→解锁自动化→更高级手动操作的循环
- 离线推进有上限；DLC 扩内容量（深渊扩展加两大技能+新 realm）
- **可学**：装备多套切换 + 被动槽（低改动高感知）；mastery 二轴做消耗方；自动化解锁曲线列入远期规划

### 4.2 修仙放置同题材

- **想不想修真**：数十级境界长线；门派贡献挂机学心法（轻量宗门形态）；灵根（金木水火土+变异灵根影响功法效率）；秘境/坊市/炼丹炼器/灵兽；轮回殿**业力**作为转生货币——结构与 SmallRpg 规划高度重合，**验证了"转生货币→兑换"与"宗门贡献→兑换"两个货币模型**
- **无极仙途**：文字修真放置；家园/风水系统；装备点化（强化）；时光秘境产长线目标物（镇派神火）——长线目标物设计可参考
- **一介散修**：修仙放置里**装备构筑做得最激进的一款**——吸血/暴击/攻速/护穿/重伤流派、装备词条+洗炼、命格洗炼、法宝养成、蕴灵；**验证了"暗黑式词条装备+洗练"在修仙放置里成立且有市场**，与本报告 1.4 的铭纹方案互为印证
- **可学**：一介散修证明词条化装备路线的市场可行性；想不想修真的贡献兑换是宗门票的轻量起点

### 4.3 通用放置里程碑

- **NGU Idle**：rebirth 货币做全局倍率；限时 challenge 换永久增益；5 套装备；augmentation 分配——挑战系统是后期内容引擎
- **Antimatter Dimensions**：**prestige 层级化**的教科书（重置→无限→永恒→现实，每层给新货币+新机制而非纯倍率）；glyph 词条构筑；后期 automator（编程式自动化）本身成为终局玩法
- **Leaf Blower Revolution**：prestige 层层叠叠+挑战层
- **Realm Grinder**：阵营选择=构筑身份（选阵营决定整条科技树走向）——"选择构筑身份"的极简实现
- **Progress Knight**：寿命制（一局=一生，转生继承技能）——时间线叙事感
- **Trimps**：automator + heirloom 词条装备

### 4.4 品类设计模式总结

1. **转生节奏**：首次重置要短（30min~2h 让玩家很快尝到甜头），每次重置解锁一点新东西（新货币/新天赋分支/新机制），间隔逐次拉长——SmallRpg 兵解转生（道韵→永久天赋）正属此类，转生票落地时按此调曲线
2. **自动化即奖励**：后期 QoL 是解锁物——SmallRpg 已有自动嗑丹/自动再战，可规划：自动出售垃圾稀有度、自动佩戴提升、自动重铸铭纹
3. **离线收益解析可解 + 有上限**（防"不上线最优"）：保持"离线=采集与修为，战斗收益在线"的现有取向
4. **显示层与爽感**：数值挂机靠指数爆发，叙事挂机靠档位跃迁——SmallRpg 走 CTEXT 叙事档位路线，但数值层仍需保证长线指数化推进感
5. **第二成长轴**：mastery/熟练度铺在内容量上（每敌人/每配方独立等级）——内容量放大器，远期候选
6. **成就/挑战**：限时挑战换永久增益是后期内容引擎——对齐 ADR-007 成就统计票
7. **内容扩充模式**：Melvor DLC、想不想修真赛季——content 包+编辑器路线（ADR-004/005）天然支持，Steam 创意工坊是远期放大器（ADR-002 已预留）
