# SPEC — 《问道长生》v2 重写：引擎/内容分离 · 桌面化 · 编辑器 · 长线内容

> 依据：CONTEXT.md（ADR 001~009）。本 spec 是全部票据的总纲。

## Problem Statement

玩家现在能在浏览器里玩到挂机修仙，但：游戏玩几小时就到头（无转生/无秘境/无成就）；内容全部硬编码在 JS 里，扩充要改代码；没有桌面版，无法上 Steam；没有编辑器，批量造内容靠手改代码；现存实现有未知 bug，用户明确表示不可信赖。

## Solution

以全新架构重写游戏核心：**引擎（零内容感知）+ 内容包（JSON+Schema）**。游戏通过 Electron 上 Windows 与 Steam（成就+云存档），Android 由 Capacitor 承载。配套独立内容编辑器：表单编辑、schema 校验、接 OpenAI 兼容 API 批量生成内容、一键导出 content 包。内容分四期扩充：转生（兵解重修/道韵）→ 秘境分层 → Boss 机制 → 成就统计。

## User Stories

### 玩家
1. 作为玩家，我想双击游戏图标就进入游戏，所以我不需要懂任何命令行。
2. 作为玩家，我想挂机修炼各技能并看到等级/经验实时变化，所以我离注意力也能成长。
3. 作为玩家，我想在斗法中看到叙事化的战斗过程（我的招式、敌人的反应、致命一击），所以挂机不是干巴巴的数字。
4. 作为玩家，我想让妖物掉落专属异宝（随机稀有度+词条），所以刷怪有开宝箱的惊喜。
5. 作为玩家，我想在修为难进一步时兵解重修，所以重新开始换来的道韵让我更强。
6. 作为玩家，我想用道韵点永久天赋（更快采集/更高攻防/更长离线），所以每次转生的选择有策略性。
7. 作为玩家，我想挑战分层秘境，层数越深怪越强、宝越好，所以我有一个明确的长期目标。
8. 作为玩家，我想打有阶段的 Boss（狂暴/机制），所以终局战斗不是数值对撞。
9. 作为玩家，我想看成就列表与统计（总击杀/总转生/历史最高），所以我的进度被记录和认可。
10. 作为玩家，我想 Steam 云存档同步进度，所以换电脑不丢档。
11. 作为玩家，我想解锁 Steam 成就，所以我的里程碑被平台记录。
12. 作为玩家，我想自动保存且关闭游戏不丢进度，所以我随时放下随时回来。
13. 作为玩家，我想离线也在修炼并领取离线收益，所以我上线有"回来了"的获得感。
14. 作为玩家，我想在乾坤袋管理装备（佩戴/卖出/对比词条），所以掉落决策有趣。
15. 作为玩家，我想在坊市买卖材料与丹药，所以卡材料时有兜底渠道。

### 内容创作者（= 玩家-创作者，将来创意工坊）
16. 作为内容创作者，我想在编辑器里用表单增删改怪物/物品/配方，所以我不需要懂代码。
17. 作为内容创作者，我想让 AI 按我的主题批量生成战斗文案词库/怪物描述，所以我不用一条条写。
18. 作为内容创作者，我想让 AI 生成的内容自动过 schema 校验，所以坏数据进不了包。
19. 作为内容创作者，我想一键导出 content 包并导入游戏，所以我做的内容立刻可玩。
20. 作为内容创作者，我想看到校验错误的具体位置与原因，所以我能修好不合规的数据。

### 开发者（= 你）
21. 作为开发者，我想引擎完全不知道任何具体内容，所以我加新技能/新玩法不改引擎。
22. 作为开发者，我想用 TypeScript 类型 + JSON Schema 双重护栏，所以 AI 与手工的坏内容都被拦住。
23. 作为开发者，我想核心逻辑可注入假时钟/假内容全速模拟（1000 秒/秒），所以回归测试秒级跑完。
24. 作为开发者，我想存档经统一接口读写（内存/localStorage/Steam Cloud 可换），所以平台适配不碰游戏逻辑。
25. 作为开发者，我想构建产物双击即玩，所以分发零摩擦。

## Implementation Decisions

### 仓库与工程
- npm workspaces monorepo（依赖全部项目内，零全局安装）：`packages/engine`（TS，零内容感知）、`packages/content`（JSON 数据 + JSON Schema + 校验器 + 内置默认包）、`packages/editor`（独立 web 工具，vite）、`packages/app-desktop`（Electron 壳 + steamworks.js）。
- 构建：vite/esbuild；测试：vitest（engine 接缝）。UI 层用轻量方案（原生 TS + 细粒度 DOM 更新，沿用现有事件委托经验；不引重框架）。

### 引擎（核心接缝）
- 引擎公共 API 是唯一核心测试接缝：`createGame({ content, save?, clock? })` → `{ tick(dt), dispatch(action), events, snapshot }`。
- `clock` 可注入（假时钟全速模拟）；`content` 为已校验的内容包对象；`events` 是结构化事件流（tick/attack/damage/loot/levelup/rebirth/unlock…），UI 与 Steam 成就都只消费事件流。
- 挂机循环、战斗解算（含暴击/减伤公式）、稀有度 roll、经验曲线、转生结算、秘境层推进、成就判定，全部是引擎机制；**参数与数据全部来自 content 包**。
- 引擎对缺内容有兜底（如未注册招式回退基础动作——旧版 bug 教训）。
- 存档经 `SaveAdapter` 接口（memory / localStorage / Electron Steam Cloud / Capacitor Preferences 可换）。
- 战斗文案系统数据化：模板片段+槽位+按伤害档分池的词库全部进 content 包；引擎提供"过滤后随机抽取"的通用抽取器（SexyMUD ADR-0011 思想）。

### Content 包与 Schema
- 首批 schema：`skills`（技能+活动）、`items`（物品/装备/丹药）、`recipes`（炼丹/炼器）、`enemies`（数值/掉落/招式）、`drops`（掉落表）、`combat-text`（词库/模板）、`rebirth`（天赋树/结算公式）、`dungeons`（秘境层表）、`bosses`（阶段脚本）、`achievements`（判定条件）、`shop`。
- 数值迁移：以现版本数值为基线迁移为首个默认 content 包（翻译工作，不是代码复用）。
- 稀有度/词条/伤害档等"档位词表"也是 content。

### 桌面壳（Electron）
- 主进程：窗口管理、自动更新占位、steamworks.js 初始化（模拟模式开关：无 AppID 时用 mock adapter，事件照常发、成就本地记账）。
- 成就：引擎事件流 → 成就判定 → steamworks.js 上报；云存档：SaveAdapter 挂 Steam Remote Storage。
- 打包：electron-builder 产出双击安装包；后续 Steam Depots 直接用其产物。

### 编辑器
- 独立 vite web 应用：左侧内容类型树、中间表单（由 schema 自动生成）、右侧校验结果与预览。
- LLM 面板：OpenAI 兼容 baseURL/key 可配置；按内容类型的提示词模板批量生成 → 自动过 schema → 人工勾选入包。
- 导入/导出：content 包 zip/JSON；"在游戏中打开"即把包放进游戏 content 目录。

### UI（全新设计）
- 仙侠主题自由发挥（不受旧版约束），保留的信息架构：技能页（顶部状态卡：等级+经验条+活动卡）、战斗页（叙事日志）、乾坤袋、坊市、设置。
- UI 只消费引擎事件流与 snapshot，不读内部状态（保 UI/逻辑解耦）。

## Testing Decisions

- **只测外部行为**：对 engine 接缝断言事件流与 snapshot，不断言内部函数调用。
- **核心接缝仅两个**：① engine API（挂机/战斗/转生/秘境/成就全走它，注入 content+假时钟）；② `validateContent`（好包通过、坏包给出字段级错误）。UI 只做渲染烟测，编辑器测校验与生成管道（LLM 用假 client）。
- 先例：旧版的"DOM 桩+vm 无头冒烟"验证过全流程，v2 用 vitest 在 engine 接缝做同类断言（不再需要 DOM 桩，engine 无 DOM）。
- 已知坑回归集（旧版踩过的）：未注册招式崩溃、日志满 40 条冻结、页面重建丢滚动、槽位 uid/id 混用、装备佩戴后属性不生效、防御减伤导致伤害档永不触发——各写一条回归用例。

## Out of Scope（本 spec 不含）

- Steam 创意工坊上传、好友排行榜（编辑器成熟后的二期）
- 真机 Steam 上线流程（Steamworks 账号/AppID 由用户并行办理；开发期模拟模式）
- 多人/联网功能；音乐音效（占位留给后续）；宗门体系（内容优先级最后）
- 旧版浏览器存档迁移

## Further Notes

- 里程碑顺序（每张票可独立验证）：① workspace 脚手架 → ② content schema+校验器+默认包迁移 → ③ 引擎核心（挂机/战斗/文案）→ ④ UI 层 → ⑤ 转生 → ⑥ 秘境 → ⑦ Boss → ⑧ 成就 → ⑨ Electron 壳+Steam 模拟 → ⑩ 编辑器（表单→校验→LLM 生成）→ ⑪ 打包一键运行。
- 用户强调：旧代码可能有 bug——重写时数值公式以 CONTEXT.md/旧版为**参考**而非权威，发现不合理即重设并记录。
